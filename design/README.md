## 三条设计原则

**1. 只有灰阶，没有第二个色相**

界面全部落在 `#0E0E0E` 到 `#F7F7F7` 之间。颜色只来自内容本身（用户的缩略图），缩略图永远是画面焦点。

深墨绿主色（`#2F6E5E`）去掉了 —— 它在绿系海报上几乎看不见，v1 已经踩过这个坑（`docs/IMPLEMENTATION.md` §1184）。

**例外一：品牌图标保留真彩色。** 图标是产品身份，不是界面装饰，单色化会丢识别度。

**例外二：OCR 命中框用橙红 `#FF5C33`。** 标注类元素的首要指标是「任何底色上都能认出」，次要才是和整体配色协调。

**2. 选中态不用描边**

| 位置 | 表现方式 |
|---|---|
| 卡片 | 投影抬升 + 缩略图右下角对勾 + 文件名加粗 |
| 颜色圆点 | 放大 1.2 倍 + 白色隔离环 + 柔和外投影 |
| 单选框 | 只显示内部实心点，外环不变色 |
| 色相滑块 | 白圆 + 双层投影 |
| 侧栏行 | 浅灰底，无边框 |

理由：界面主体是用户的设计稿，卡片本身已有圆角边框。再叠深色描边会「框死」卡片，跟三栏浮起、卡片浮起的层次语言冲突。

**3. 圆角加大 / 字号收敛**

卡片 18 / 面板 22 / 缩略图 14 —— 差 4px 形成同心倒角。
字号从 v1 的 6 个碎档（8.5–11）收敛为 11 / 12 / 13 / 15 / 17 / 22，最小 11px。

## 实现要点（踩过的坑）

### 图标一律用 SVG，不用 Unicode 字形

`▴ ▾ ✓ ▲ ▼ ▸` 这类字形按文字基线排布，`place-items: center` 对超出行盒的字形不起作用：

- 11px 高的格子里放 `▴`（行高 18.6px）→ 实测**偏下 4.20px**
- 换成 7×4 的 SVG → 偏移 **0.00px**

### 缩进必须是层级的唯一表达，不能被任何元素抵消

旧版目录树：

```
.tree-node.d1 { padding-left: 20px }   /* 父行 */
.tree-node.d2 { padding-left: 38px }   /* 子行 */
gap: 6px  +  caret 12px

父行：20 + 12 + 6 = 38
子行：38
→ 完全相等，父子圆点和文字精确重合（实测都是 79.3px）
```

现在用 `--depth` 变量，每层 +16px，父行 caret 与分组标题左对齐。

### `margin:0 -10px` + `padding:0 10px` 的复用陷阱

`.radio-row` / `.tree-node` 用这对内外边距让 hover 背景铺到面板边缘。**在别处复用时不能内联 `margin:0` 覆盖它** —— 那会把负边距抵消，内容比同面板的开关多缩进 10px（实测偏差 10.0px）。

### CSS Grid 子项必须 `min-height: 0`

`grid-template-rows: 64px minmax(0, 1fr)` —— 只写 `1fr` 时最小值是 `auto`，内容超高会把行撑破视口（实测 900px 撑到 925px）。

### 列表视图的缩略图要 cover，不是 contain

沿用网格的 `object-fit: contain` 会按原图比例撑高（实测 52×69），被 52×52 容器裁成中间一条，只剩半个标题。

### 滑块轨道要有默认底色

容差滑块不传 `track` 参数，透明轨道上只有一颗悬空圆点。默认 `background: var(--surface-4)`。

## 响应式

1440 是设计基准。

| 宽度 | 侧栏 | 详情 | 搜索框 | 卡片最小宽 |
|---|---|---|---|---|
| > 1320 | 272 | 376 | flex 弹性，上限 640 | 200 |
| 1320–1160 | 240 | 320 | 下限 200 | 168 |
| < 1160 | 216 | 300 | 下限 180 | 168 |

搜索框宽度是弹性的（`flex: 1 1 auto`），吃掉品牌与模式切换之间的全部剩余空间 ——
它是这屏最常操作的地方，窗口变宽时优先长它。

**窄屏的让位顺序**（按代价从小到大）：

| 断点 | 让掉什么 | 为什么 |
|---|---|---|
| ≤ 1240 | 文字索引按钮只留图标 | 它是「图中文」模式的附属功能 |
| ≤ 1120 | 计数胶囊 | 它是信息不是操作，每张卡片上也写着同样的数 |
| ≤ 940 | 拖图胶囊收成纯图标 | 图标本身语义完整（向上的箭头） |

标题「全部文件」和搜索框输入区**永不让位** —— 前者是这一屏的定位锚点，
后者是主操作。

### 一个踩过的坑

把 `.searchbox` 从固定宽改成 `flex: 1 1 auto` 时，两条老媒体查询里还留着
`width: 280px` / `width: 220px`。flex 容器的 `flex-basis: auto` 会取 `width`
当基准，等于**在窄屏把弹性伸展关掉了** —— 实测 1000px 时搜索框只有 332px，
本该 380+。改成 `min-width` 后恢复。

**教训**：元素从固定宽改弹性时，要全表搜它的 `width` 声明，媒体查询里的也算。

## v3 增量（相对上面 v2 描述）

### 1. 拖图入口并进搜索框

原 `.dropzone` 是顶栏独立一格（148px）。顶栏挤了 9 个元素，1440 才勉强放下。
改成搜索框内的白色胶囊 `.dz-chip`（30px 高，白底 + 1px 内描边）：

```
空态:  ⌕ 搜文件名或路径…              [↑ 拖图搜索]
有图:  ⌕ 搜文件名或路径…         [● drop-test.png ×]
```

### 2. 文字索引按钮移到主区标题栏

它本质是「图中文」模式的附属功能，不该占顶栏 147px。现在排在 `.main-tools` 里。

### 3. 单选框尺寸修正

原 **13px 外径 / 1.5px 描边** → 内径 11px（1.5 在 1x 屏被舍成 1），
黑点 6px，留白 (11-6)/2 = **2.5px 半像素** → 浏览器往右下舍入 → 实测偏 **+0.5px**。

改为 **14px / 1px** → 内径 12px，留白 (12-6)/2 = **3px 整数**。
实测 DPR 1 / 1.5 / 2 / 3 偏心全为 `0.000px`。

### 4. 格式分组按数量降序 + 折叠

后端返回按扩展名字母序，导致 XLS(2)、DOCM(1) 排前排，PSD 5364 排中间。
改为**按数量降序**，默认只显示前 12 个 + 「+N 种」按钮。

**已选中的格式永远显示**，不因折叠消失 —— 否则用户看不出为什么结果变少。

### 5. 分组间距收紧

`padding 11/5 → 9/3`、`margin-top 5 → 3`、`padding-top 12 → 10`、底部留白 `14 → 8`。

侧栏内容高：**896px → 784px**（可视区 780px），880 高窗口下溢出 116px → 4px。

import sys; sys.path.insert(0, '.')
from PIL import Image
from core import ocr
im = Image.open('你的截图.png').convert('RGB')
t = ' '.join(x for x, _s, _b in ocr.recognize(
    im.resize((im.width * 2, im.height * 2), Image.LANCZOS)))
for w in ['真实项目名', '客户名']:
    print(w, '❌ 漏了' if w in t else 'OK')
PY
